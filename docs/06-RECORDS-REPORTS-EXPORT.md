# Records, Reports, Export

The three output-shaped subsystems: the scan/OCR pipeline (`RecordsKit`), the
generated PDF reports (`ReportKit`), and the backup format (`ExportKit`). All
on-device; none of it touches the network (`01-ARCHITECTURE.md` §8).

## 1. Document capture

Inputs, all landing in the same review flow:

- **Camera scan** — `VNDocumentCameraViewController` (multi-page, auto-crop,
  perspective correction) → PDF.
- **Photo import** — `PhotosPicker` → image stored as-is.
- **File import** — Files app / share extension → PDF or image copied into the
  vault. Share extension ships Phase 4.

Files are written to
`Application Support/Attachments/<petID>/<uuid>.<ext>` with
`.completeUnlessOpen` protection; the `PetDocument` row stores the relative
path (`02-DATA-MODEL.md` §6). Originals are never re-encoded — OCR quality and
evidentiary value beat storage savings.

## 2. OCR and extraction

Pipeline (all in `RecordsKit`, background on `DataActor`'s executor):

```
PDF/image → page rasters → VNRecognizeTextRequest (.accurate, en-US)
        → per-page text + bounding boxes → ocrText (searchable)
        → heuristic extraction → ReviewSuggestions
```

Heuristics (v1, deliberately dumb and transparent):

- **Date**: `NSDataDetector` date matches, scored by position (top third of
  page 1 wins) and plausibility (past year > future).
- **Clinic**: fuzzy match of OCR lines against existing `Contact` names; else
  the top-of-page line with clinic-word hints (Veterinary, Animal, Clinic,
  Hospital).
- **Kind**: keyword vote (invoice/receipt → invoice; vaccine names → vaccine
  record; "CBC"/"chemistry" → lab result).
- **Medication names**: OCR tokens matched against the pet's existing meds and
  the bundled toxicity list's name corpus — suggested as tags only.

Everything lands in the **review sheet** as editable suggestions with
confidence dots; nothing auto-commits (`07-BUILD-ROADMAP.md` risk register:
"framed as suggestions, never auto-committed"). `ocrConfidence` below 0.4
suppresses suggestions entirely — the document is still filed and viewable.

Test fixtures: ~20 redacted real vet documents (invoices, vaccine certificates,
lab panels, discharge instructions) in the `RecordsKit` test bundle, asserted
on extraction fields (`07-BUILD-ROADMAP.md`, testing strategy).

## 3. Generated reports (`ReportKit`)

Six PDFs, each a SwiftUI view rendered via `ImageRenderer` into a PDF context —
no HTML, no string concatenation. All render offline in under 2 s on an
iPhone 12. Every report footer: "Generated by FloofSync · <date> · Not
veterinary advice."

| Report | Contents | Primary audience |
|---|---|---|
| **Vet visit summary** | Pet header, active meds with current schedules, adherence chart for a selected range (given/partial/refused/missed per day), weight trend, recent logs, questions field | The vet, before an appointment |
| **Sitter care brief** | Per-pet: photo, feeding plan, med schedule in plain words ("2 tablets with breakfast"), quirks, emergency contacts, vet, poison control | A sitter with no app |
| **Lost-pet poster** | LOST + species, big photo, name, marks, last-seen area (typed), owner phone (user chooses which), microchip number, tear-off strips variant | Printing at 3 AM |
| **Pet ID card** | Credit-card layout, front/back: photo, name, chip, vet, owner phone, critical meds/allergies | Wallet / boarding |
| **Groomer brief** | Style notes + reference photos, blade lengths, shampoo constraints, behavior notes, cadence history | The groomer |
| **Adherence report** | The vet summary's adherence section alone, for a date range, with the schedule-revision timeline annotated | Specialist / insurance |

Poster and ID card also export as PNG for sharing/social. All reports respect
the unit settings and are VoiceOver-readable before render (they're SwiftUI
views).

## 4. Backup: the `.floofsync` bundle

A ZIP with a stable, documented layout — the round-trip guarantee
(`00-OVERVIEW.md` §9: export → wipe → import restores every byte):

```
backup.floofsync (zip)
├─ manifest.json        { formatVersion: 1, appVersion, createdAt,
│                         entityCounts, attachmentCount, encrypted: false }
├─ data/
│   ├─ pets.json        one array per entity kind; every field, UUIDs verbatim
│   ├─ medications.json (with base64 scheduleData/endPolicyData preserved bit-exact)
│   ├─ doseLogs.json …  (one file per @Model kind in 02-DATA-MODEL)
└─ attachments/<petID>/<uuid>.<ext>   raw original bytes
```

Rules:

- **Forward-only versioning**: `formatVersion` gates import; a newer bundle in
  an older app fails with a clear message, never a partial import.
- **Import is transactional**: staged into a temporary store + temp attachment
  dir, verified (counts, referential integrity, attachment hashes from the
  manifest), then swapped in. A failed import changes nothing.
- **Merge is out of scope for v1** — import replaces or restores-into-empty,
  chosen explicitly by the user with a destructive-action confirm.
- **Optional encryption**: passphrase → HKDF-SHA256 → AES-GCM over the whole
  zip; `manifest.json` stays outside the encrypted payload so the importer can
  say "this backup is encrypted" before asking. The UI warns that a forgotten
  passphrase is unrecoverable (`01-ARCHITECTURE.md` §8).
- **Round-trip property test** (`ExportKitTests`): a randomized database
  (every entity kind, every enum case, unicode strings, attachment blobs) →
  export → import into a fresh store → deep equality including attachment
  bytes. This test is the format's contract.

CSV exports (dose log, weights) are one-way conveniences, not backups, and say
so in the UI.

## 5. Weekly auto-backup

When enabled (off by default): on the first app-open after 7 days since the
last backup, write a `.floofsync` bundle to the user's chosen Files location
(security-scoped bookmark), keep the last 4, and show a quiet confirmation
toast. Never runs in the background (no reliable window; `01-ARCHITECTURE.md`
§5) — piggybacks on real app opens.
